# output-styles/

One `.md` per style. An output style replaces how an agent writes and reports — evidence standards,
status reporting, tone. It doesn't add capability, and only one is active at a time.

If you're writing "when the user asks X, do Y," that's a skill, not a style.

Write in second person, prescriptive and concrete — "state the command and its exit code" beats "be
rigorous." Name the failure mode a rule exists to prevent, so it survives cases the rule didn't
anticipate.

Where a style is tuned per model, suffix the filename with the model
(`structured-engineering-opus-5.md`). If two variants have diverged into different philosophies, give
them different names.
